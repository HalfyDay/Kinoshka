=== Действенный метод извлечения видеопотоков Kodik (2025/2026) ===

1. ПОЛУЧЕНИЕ ПЛЕЕРА И ИЗВЛЕЧЕНИЕ ПАРАМЕТРОВ (API PAYLOAD)
При обращении к странице серии (например, https://vsh.my/seria/424881/5aa63006d467875cf14b94652d3474ab/720p),
из HTML-кода страницы необходимо извлечь следующие переменные с помощью регулярных выражений:
- d (domain): var domain = '...' (или var d = '...')
- d_sign: var d_sign = '...'
- pd: var pd = '...'
- pd_sign: var pd_sign = '...'
- ref: var ref = '...'
- ref_sign: var ref_sign = '...'
- type: vInfo.type = '...'
- hash: vInfo.hash = '...'
- id: vInfo.id = '...'

Также в POST-запрос добавляются постоянные параметры:
- bad_user: "false"
- cdn_is_working: "true"
- info: "{}"

2. ДИНАМИЧЕСКИЙ ПОИСК ЭНДПОИНТА POST API
Эндпоинт API Kodik меняется динамически (например, /ftor, /tri, /gvi).
Путь содержится в JS-файле плеера (найдите тег <script src="...assets/js/app...js">).
Из содержимого JS-файла извлеките base64 строку с помощью регулярного выражения:
\$\.ajax[^)]+atob\([\"'](\w+=*)[\"']\)
Декодируйте полученную строку из Base64 (например, "L2Z0b3I=" -> "/ftor").
Используйте полученный адрес для отправки POST запроса с телом (payload), собранным в п.1.

3. ДЕШИФРОВКА ССЫЛОК НА ВИДЕО (ROT18 + BASE64)
В ответе POST-запроса возвращается JSON объект вида {"links": {"360": [{"src": "..."}], "480": ..., "720": ...}}.
Для каждого качества значение в поле "src" дешифруется следующим образом:
- Если ссылка оканчивается на ".m3u8", она уже в открытом виде.
- Иначе: к строке применяется кастомный шифр ROT18 (сдвиг латинских букв A-Z и a-z на 18 позиций назад/вперед в алфавите: (code - offset + 18) % 26 + offset).
- Полученная после ROT18 строка дополняется символами "=" до выравнивания Base64 (если требуется) и декодируется стандартным Base64.
- Результатом является прямая ссылка на HLS манифест (.m3u8).
