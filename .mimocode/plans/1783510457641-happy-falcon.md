# План улучшений приложения Kinoshka

## Обзор приложения

**Kinoshka** — Android-приложение для просмотра фильмов (Кинопоиск API) и аниме (Shikimori API + Kodik/AniLiberty) с встроенным MPV-плеером.

**Стек:** Kotlin, Jetpack Compose, Retrofit + Gson, Room, Koin, Coil, MPV, Navigation Compose, Media3/ExoPlayer

---

## 1. Архитектурные улучшения

### 1.1 FilmsViewModel — God Object (~1150 строк)
- **Проблема:** `FilmsViewModel` содержит всю логику: домашний экран, детали, профиль, Shikimori-синхронизацию, календарь, ленту, настройки, библиотеку. Это делает код трудноподдерживаемым.
- **Решение:** Разделить на специализированные ViewModel'и:
  - `HomeViewModel` — каталог, поиск, фильтры, пагинация
  - `DetailsViewModel` — детали фильма/аниме, профиль пользователя
  - `ProfileViewModel` — профиль, Shikimori OAuth
  - `SettingsViewModel` — настройки приложения
  - `AnimeCalendarViewModel` — календарь аниме
  - `AnimeFeedViewModel` — лента новостей

### 1.2 Отсутствие DI для Repository/ViewModel
- **Проблема:** `FilmsRepository` и `AnimeRepository` создаются вручную в `KinoApp.kt`. ViewModel создаётся через `FilmsViewModelFactory`.
- **Решение:** Зарегистрировать все репозитории и ViewModel'и в Koin (уже настроен для mpvEx-модулей).

### 1.3 Два отдельных API клиента без единого интерфейса
- **Проблема:** `KinopoiskApi` и `ShikimoriApi` создаются отдельно через `ApiClient`, но не инжектируются.
- **Решение:** Вынести создание Retrofit-клиентов в Koin-модуль.

## 2. Проблемы безопасности

### 2.1 Trust-all SSL в AnimeStreamResolver
- **Проблема:** `AnimeStreamResolver.kt:52-61` — OkHttp-клиент с `TrustManager`, который принимает ВСЕ сертификаты. Это уязвимость MITM.
- **Решение:** Убрать trust-all, использовать стандартный SSL. Если нужен fallback — использовать пиннинг сертификатов или отдельный клиент для конкретных хостов.

### 2.2 API-ключи в SharedPreferences
- **Проблема:** Shikimori OAuth-токены хранятся в SharedPreferences (`ShikimoriAuthStore`), доступных root-пользователям.
- **Решение:** Использовать `EncryptedSharedPreferences` (AndroidX Security) для хранения токенов.

### 2.3 ProGuard отключён для release
- **Проблема:** `app/build.gradle.kts:58` — `isMinifyEnabled = false`. Release-сборка не обфусцируется, увеличивает размер APK, уязвима к реверс-инжинирингу.
- **Решение:** Включить `isMinifyEnabled = true` и `isShrinkResources = true`, добавить ProGuard-правила для Retrofit/Gson/Room/Koin.

## 3. Производительность

### 3.1 Кэширование в репозиториях
- **Проблема:** `FilmsRepository` и `AnimeRepository` хранят кэш в `ConcurrentHashMap` с TTL 3 дня. Кэш неограничен по размеру — утечка памяти при долгой сессии.
- **Решение:** Добавить `maxSize` для каждого кэша или использовать LRU-кэш (например, `LruCache`).

### 3.2 buildLibraryItems() пересоздаётся слишком часто
- **Проблема:** `FilmsViewModel.kt:1034` — `buildLibraryItems()` вызывается при каждом изменении состояния, включая несвязанные обновления (например, `setShowFpsCounter`).
- **Решение:** Кэшировать результат `buildLibraryItems()` и пересчитывать только при изменении связанных данных (история, профили, Shikimori-ставки).

### 3.3 Coroutines и threading
- **Проблема:** `rateLimitRetryInterceptor` (`ApiClient.kt:54-84`) использует `Thread.sleep()` в OkHttp-интерцепторе, блокируя поток OkHttp.
- **Решение:** Заменить на асинхронный retry с `delay()` в coroutine scope или использовать `OkHttp` retry без блокировки.

### 3.4 Loading 40 аниме-деталей последовательно
- **Проблема:** `FilmsViewModel.kt:226` — `missingDetailsRates.take(40).forEach { ... }` загружает детали последовательно в одном coroutine.
- **Решение:** Использовать `async` для параллельной загрузки с ограничением параллелизма (например, `Semaphore`).

## 4. Качество кода

### 4.1 Дублирование кода кэширования
- **Проблема:** `FilmsRepository` и `AnimeRepository` содержат идентичные реализации кэша (`CacheEntry`, `getIfFresh`, `ConcurrentHashMap`).
- **Решение:** Вынести общую логику кэширования в базовый класс или утилиту.

### 4.2 Дублирование кода пагинации
- **Проблема:** `loadDiscoverFirstPage/loadDiscoverNextPage` и `loadSearchFirstPage/loadSearchNextPage` — 4 метода с почти идентичной логикой.
- **Решение:** Рефакторинг в обобщённый метод загрузки с параметрами.

### 4.3 Дублирование кода синхронизации Shikimori
- **Проблема:** Логика обновления/создания `userRate` с retry-механизмом повторяется в `saveUserProfile` и `updateAnimeProgress`.
- **Решение:** Вынести в отдельный метод `syncUserRateWithShikimori()`.

### 4.4 Хардкод строк
- **Проблема:** Русские строки разбросаны по коду (Toast, заголовки, описания). Нет локализации.
- **Решение:** Вынести все строки в `strings.xml` с поддержкой `strings.xml (ru)`.

## 5. UI/UX улучшения

### 5.1 Отсутствие pull-to-refresh
- **Проблема:** На главном экране нет жеста pull-to-refresh для обновления контента.
- **Решение:** Добавить `PullToRefreshBox` (Material3) для `HomeScreen`.

### 5.2 Ограниченная навигация между сериями
- **Проблема:** `MpvExPlayerScreen` принимает `onNextEpisode`/`onPrevEpisode`, но всегда передаёт `null`.
- **Решение:** Реализовать навигацию между сериями внутри MPV-плеера.

### 5.3 Отсутствие анимаций переходов
- **Проблема:** Большинство переходов между экранами используют простой `fadeIn`/`fadeOut`. Нет shared element transitions.
- **Решение:** Добавить shared element transitions для постеров при переходе "список → детали".

### 5.4 Нет индикатора прогресса загрузки
- **Проблема:** При загрузке更多 (infinite scroll) нет визуального индикатора внизу списка.
- **Решение:** Добавить `CircularProgressIndicator` в конец списка при `loadingMore = true`.

## 6. Функциональные улучшения

### 6.1 Поиск по истории
- **Проблема:** Нет возможности искать по уже просмотренным фильмам/аниме.
- **Решение:** Добавить фильтрацию по истории вкладки "Библиотека".

### 6.2 Уведомления о новых сериях
- **Проблема:** Нет push-уведомлений о новых сериях аниме.
- **Решение:** Реализовать WorkManager + notification channel для мониторинга календаря аниме.

### 6.3 Автовоспроизведение следующей серии
- **Проблема:** После завершения серии нет автоматического перехода к следующей.
- **Решение:** Реализовать логику автовоспроизведения с учётом настройки `PlaybackSequenceOption`.

### 6.4 Кэширование офлайн
- **Проблема:** При отсутствии интернета приложение показывает ошибку, хотя данные могли бы быть в кэше.
- **Решение:** Реализовать стратегию `Cache-Control: only-if-cached` при offline-режиме.

## 7. Тестирование

### 7.1 Отсутствуют unit-тесты
- **Проблема:** Нет ни одного unit-теста в проекте.
- **Решение:** Добавить тесты для:
  - `SearchQueryUtils` (простой, изолированный)
  - `FilmsRepository` (с моком API)
  - `UserStateStore` (с моком SharedPreferences)
  - `AnimeStreamResolver` (с моком HTTP)

### 7.2 Отсутствуют UI-тесты
- **Проблема:** Нет инструментальных тестов.
- **Решение:** Добавить Compose UI-тесты для ключевых экранов.
