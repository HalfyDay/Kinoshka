# Plan: Fix Kodik and Aniliberty Player Issues

## Problem Summary

**Kodik**: All anime fail with error "Некорректная ссылка на видеопоток" + garbled string.  
**Aniliberty**: Wrong anime plays for some titles (Attack on Titan → Nagatoro, Death Note → film, One Punch Man → "smegly" instead of episodes).

## Root Causes

### Kodik: Hardcoded ROT18
The app uses `decryptRot18()` which hardcodes a ROT-18 shift. However, Kodik can use **any ROT value from 0-25**. The `decodeKodikUrl()` function applies ROT18 unconditionally and then Base64-decodes, producing garbage when the actual ROT is different.

**Reference**: The AnimeParsers Python library (`_convert` method) iterates ROT 0-25 and validates each decoded result by checking for `mp4:hls:manifest` in the output string. It also caches the working ROT step for subsequent calls.

**Error evidence**: The user's garbled string `iPZ0kPU6Tg9hi3sck29aj2ZrHO4cG29bT2NciE1t|PHhHFR xHFUdWBIqWLUgHLs4HBCeVBG1VhQeHBJtVERuGrCfVh...` is what you get when you apply ROT18 to a URL encoded with a different ROT value.

### Aniliberty: No title validation on release match
`findAniLibertyRelease()` → `firstReleaseMatchingAlias()` picks the first release whose alias/title-slug matches the search query. When Anilibria returns multiple releases (anime, film, related titles), the wrong one can be selected because:
- No type filtering (anime-serial vs film)
- No fuzzy title comparison against the expected `animeTitle`
- The free-text search (`/app/search/releases`) doesn't filter by type

#### 1. Fix Kodik URL decryption (lines 876-900)

Replace the hardcoded ROT18 with an iterative ROT 0-25 approach, matching the AnimeParsers library:

```kotlin
private fun decodeKodikUrl(value: String): String {
    val clean = value.replace("\\/", "/")
    if (clean.endsWith(".m3u8")) {
        return if (clean.startsWith("http")) clean else if (clean.startsWith("//")) "https:$clean" else clean
    }
    // Try cached ROT step first
    val cachedStep = lastWorkingRotStep
    if (cachedStep != null) {
        val result = tryRotDecode(clean, cachedStep)
        if (result != null) return result
    }
    // Iterate all ROT values 0-25
    for (rot in 0 until 26) {
        val result = tryRotDecode(clean, rot)
        if (result != null) {
            lastWorkingRotStep = rot
            return result
        }
    }
    return clean
}

private fun tryRotDecode(encoded: String, rot: Int): String? {
    return runCatching {
        val shifted = String(encoded.map { ch ->
            when {
                ch in 'A'..'Z' -> ((ch.code - 65 + rot) % 26 + 65).toChar()
                ch in 'a'..'z' -> ((ch.code - 97 + rot) % 26 + 97).toChar()
                else -> ch
            }
        }.toCharArray())
        val padded = shifted.padEnd(((3 - (shifted.length % 3)) % 3) + shifted.length, '=')
            .let { if (it.endsWith("==") || it.endsWith("=")) it else "$it==" }
        val decodedBytes = Base64.getDecoder().decode(padded)
        val decoded = String(decodedBytes, Charsets.UTF_8)
        if (decoded.contains("mp4") || decoded.contains(".m3u8") || decoded.startsWith("http") || decoded.startsWith("//")) {
            if (decoded.startsWith("http")) decoded else if (decoded.startsWith("//")) "https:$decoded" else decoded
        } else null
    }.getOrNull()
}

@Volatile
private var lastWorkingRotStep: Int? = null
```

Remove the old `decryptRot18` function (no longer needed).

```kotlin
private fun titlesMatch(expected: String, actual: String): Boolean {
    val normalize = { s: String ->
        s.lowercase().replace(Regex("[^a-zа-яё0-9]+"), " ").trim()
    }
    val nExpected = normalize(expected)
    val nActual = normalize(actual)
    return nExpected == nActual || nExpected.contains(nActual) || nActual.contains(nExpected)
}
```
