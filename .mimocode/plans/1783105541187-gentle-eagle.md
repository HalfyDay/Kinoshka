# Оптимизация отображения списка серий аниме

## Проблема
При нажатии кнопки "Смотреть" и отображении sheet с выбором серий/озвучки —列表 рендерится медленно, особенно при переключении между режимами "Сначала серии" и "Сначала озвучки". Основные причины: повторные вычисления в composition, отсутствие ключей LazyColumn, синхронное чтение SharedPreferences в composition.

## Файлы для изменения

### 1. `AnimePlaybackSelectionScreen.kt` — основные оптимизации

#### 1.1 Предвычисление карты количества озвучек на серию

**Проблема**: В `SelectEpisodeStep` (строка 837-839) для КАЖДОЙ видимой серии вычисляется `trCount` — сканирование всех озвучек. При 20+ озвучках × 50+ серий это O(T×E) на каждый visible item.

**Решение**: Вычислить `Map<Int, Int>` (номер серии → количество озвучек) один раз при загрузке `allTranslations` и передавать в `SelectEpisodeStep`.

```kotlin
// Внутри AnimePlaybackSelectionScreen, после загрузки allTranslations (после строки 110):
val episodeTranslationCountMap = remember(allTranslations) {
    buildMap {
        for (tr in allTranslations) {
            for (ep in tr.episodes) {
                merge(ep.number, 1, Int::plus)
            }
        }
    }
}
```

Передать `episodeTranslationCountMap` в `SelectEpisodeStep` и использовать вместо per-item вычисления.

#### 1.2 Добавление ключей LazyColumn

**Проблема**: `items(sortedEpisodes)` (строка 788) и `items(translations)` (строка 591) не используют `key`. Compose не может эффективно переиспользовать items при сортировке.

**Решение**:

```kotlin
// SelectEpisodeStep, строка 788:
// Было:  items(sortedEpisodes) { ep ->
// Стало:
items(sortedEpisodes, key = { it.number }) { ep ->

// SelectTranslationStep, строка 591:
// Было:  items(translations) { tr ->
// Стало:
items(translations, key = { it.translationId }) { tr ->
```

#### 1.3 Предвычисление объединённого списка серий для EPISODES_FIRST

**Проблема**: Строка 404-408 выполняет `flatMap { it.episodes }.distinctBy { it.number }` каждый раз при переключении шага. Это создаёт промежуточные списки.

**Решение**: Предвычислить объединённый список серий один раз как derived state:

```kotlin
// Внутри AnimePlaybackSelectionScreen, после загрузки allTranslations:
val mergedEpisodes = remember(allTranslations) {
    allTranslations
        .flatMap { it.episodes }
        .distinctBy { it.number }
        .sortedBy { it.number }
}

val mergedEpisodesBySource = remember(allTranslations) {
    allTranslations
        .groupBy { it.source }
        .mapValues { (_, translations) ->
            translations
                .flatMap { it.episodes }
                .distinctBy { it.number }
                .sortedBy { it.number }
        }
}
```

Затем в `SelectionStep.EPISODE` (строка 404-408):

```kotlin
// Было:
val episodesSource = when {
    selectedTranslation != null -> selectedTranslation!!.episodes
    selectedSourceType != null -> allTranslations.filter { it.source == selectedSourceType }.flatMap { it.episodes }.distinctBy { it.number }
    else -> allTranslations.flatMap { it.episodes }.distinctBy { it.number }
}

// Стало:
val episodesSource = when {
    selectedTranslation != null -> selectedTranslation!!.episodes
    selectedSourceType != null -> mergedEpisodesBySource[selectedSourceType!!] ?: mergedEpisodes
    else -> mergedEpisodes
}
```

#### 1.4 Перенос чтения SharedPreferences в coroutine

**Проблема**: Строка 113-123 читает SharedPreferences синхронно в composition.

**Решение**: Использовать `LaunchedEffect` для асинхронного чтения:

```kotlin
var lastPlayback by remember { mutableStateOf<LastPlaybackInfo?>(null) }

LaunchedEffect(shikimoriId, allTranslations) {
    lastPlayback = withContext(Dispatchers.IO) {
        val prefs = context.getSharedPreferences("anime_playback_prefs", Context.MODE_PRIVATE)
        val src = prefs.getString("last_source_$shikimoriId", null)
        val trId = prefs.getString("last_translation_id_$shikimoriId", null)
        val trTitle = prefs.getString("last_translation_title_$shikimoriId", null)
        val epNum = prefs.getInt("last_episode_num_$shikimoriId", -1)
        if (src != null && trId != null && trTitle != null && epNum != -1) {
            LastPlaybackInfo(src, trId, trTitle, epNum)
        } else null
    }
}
```

#### 1.5 Использование stable-типа для эпизодов в LazyColumn

**Проблема**: `AnimeEpisode` является `data class`, но передаётся как элемент списка. Compose сравнивает по structural equality. Для further optimization можно использовать `key` (уже решено в 1.2) + `contentType`.

```kotlin
items(
    sortedEpisodes,
    key = { it.number },
    contentType = { "episode" }
) { ep ->
```

### 3. `AnimeStreamResolver.kt` — оптимизация кэша ключей

**Проблема**: Кэш `prefetchAllMediaCache` использует ключ `"$shikimoriId:$animeTitle"`. Если title немного отличается — кэш промахивается.

**Решение**: Нормализовать ключ кэша:

```kotlin
// В prefetchAllMedia (строка 111):
// Было:  val cacheKey = "$shikimoriId:$animeTitle"
// Стало:
val cacheKey = "$shikimoriId:${animeTitle.trim().lowercase()}"
```

Это небольшое улучшение — при повторных открытиях одного аниме кэш будет命中 чаще.

## Верификация

1. Собрать проект: `./gradlew assembleDebug`
2. Проверить открытие sheet при нажатии "Смотреть" для аниме с 20+ озвучками
3. Проверить оба режима: "Сначала серии" и "Сначала озвучки"
4. Проверить переключение сортировки (ascending/descending) — должно быть плавно
5. Проверить Quick Continue карточку — должна появляться при наличии сохранённого прогресса
6. Проверить переключение вкладок Озвучка/Субтитры
7. Мониторинг через Compose compiler reports: `./gradlew assembleRelease` с `-Pcompose compiler.reports=true`
