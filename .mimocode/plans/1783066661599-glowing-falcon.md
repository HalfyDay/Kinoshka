## 2. CRITICAL: Fix Shikimori API Calls for User Rates

**Files to modify:**
- `app/src/main/java/hd/kinoshka/app/data/api/ShikimoriApi.kt`
- `app/src/main/java/hd/kinoshka/app/data/model/ShikimoriModels.kt` (add request body classes)

### Root Cause Analysis:
The anime progress is NOT being saved to Shikimori because **the API calls are using incorrect parameter format**.

**Current implementation (WRONG):**
```kotlin
@POST("api/v2/user_rates")
suspend fun createUserRate(
    @Header("Authorization") token: String,
    @Query("user_rate[user_id]") userId: Int,  // ❌ Sends as URL query parameter
    @Query("user_rate[target_id]") targetId: Int,  // ❌ Sends as URL query parameter
    @Query("user_rate[status]") status: String,  // ❌ Sends as URL query parameter
    @Query("user_rate[episodes]") episodes: Int = 0,  // ❌ Sends as URL query parameter
    @Query("user_rate[score]") score: Int = 0  // ❌ Sends as URL query parameter
): ShikimoriUserRate
```

This sends a request like:
```
POST /api/v2/user_rates?user_rate[user_id]=123&user_rate[target_id]=456&user_rate[status]=watching
```

**What Shikimori API expects (CORRECT):**
According to https://shikimori.io/api/doc/2.0/user_rates/create.html:

```kotlin
@POST("api/v2/user_rates")
suspend fun createUserRate(
    @Header("Authorization") token: String,
    @Body userRate: UserRateRequest  // ✅ Sends as JSON body
): ShikimoriUserRate
```

The request body should be:
```json
{
  "user_rate": {
    "user_id": 123,
    "target_id": 456,
    "target_type": "Anime",
    "status": "watching",
    "episodes": 2,
    "score": 10
  }
}
```

### Changes:

1. **Add request body data class** in `ShikimoriModels.kt`:
```kotlin
data class UserRateRequest(
    @SerializedName("user_rate") val userRate: UserRateData
)

data class UserRateData(
    @SerializedName("user_id") val userId: Int,
    @SerializedName("target_id") val targetId: Int,
    @SerializedName("target_type") val targetType: String = "Anime",
    @SerializedName("status") val status: String? = null,
    @SerializedName("episodes") val episodes: Int? = null,
    @SerializedName("score") val score: Int? = null,
    @SerializedName("text") val text: String? = null,
    @SerializedName("rewatches") val rewatches: Int? = null
)

data class UserRateUpdateRequest(
    @SerializedName("user_rate") val userRate: UserRateUpdateData
)

data class UserRateUpdateData(
    @SerializedName("status") val status: String? = null,
    @SerializedName("episodes") val episodes: Int? = null,
    @SerializedName("score") val score: Int? = null,
    @SerializedName("text") val text: String? = null,
    @SerializedName("rewatches") val rewatches: Int? = null
)
```

2. **Update ShikimoriApi.kt** to use `@Body` instead of `@Query`:
```kotlin
@POST("api/v2/user_rates")
suspend fun createUserRate(
    @Header("Authorization") token: String,
    @Body userRate: UserRateRequest
): ShikimoriUserRate

@PATCH("api/v2/user_rates/{id}")
suspend fun updateUserRate(
    @Header("Authorization") token: String,
    @Path("id") rateId: Int,
    @Body userRate: UserRateUpdateRequest

```

3. **Update AnimeRepository.kt** to pass the correct body:
```kotlin
suspend fun createUserRate(token: String, userId: Int, targetId: Int, status: String, episodes: Int = 0, score: Int = 0): ShikimoriUserRate? {
```

## 5. Fix Anime Display from Shikimori

**Files to modify:**
- `app/src/main/java/hd/kinoshka/app/ui/screens/FilmsViewModel.kt`
- `app/src/main/java/hd/kinoshka/app/data/repo/AnimeRepository.kt`
- `app/src/main/java/hd/kinoshka/app/data/local/UserStateStore.kt`

### Root Cause Analysis:
The display issues (posters disappearing, titles becoming "Аниме#123", incorrect progress) occur because:

1. **Cache expiration**: `AnimeRepository` uses a 3-day in-memory cache (`ttlMs`). After cache expires, `ShikimoriAnimeItem` objects in `cachedShikimoriRates` lose their `anime` field data.

2. **Null anime data**: In `ShikimoriUserRate.toLibraryUiItem()` (line 994), if `anime` is null:
   - `appTitle` falls back to "Аниме#$actualTargetId" (line 1000)
   - `appPoster` becomes null (line 1001)
   - `totalEpisodes` becomes null (line 1029)

3. **Progress calculation**: Without `totalEpisodes`, the `toWatchProgressUi()` function returns null (line 1493-1497) because both `totalEpisodesSafe` and `totalSeasonsSafe` are null.

### Changes:
1. **Persist anime details locally** in `UserStateStore`:
   - Add a map to cache Shikimori anime details (id → title, poster, episodes)
   - This survives app restarts and cache expiration

2. **Restore anime details on startup** in `refreshShikimoriAuth()`:
   - When fetching rates, check local cache first before calling API
   - Update local cache when API returns fresh data

3. **Fallback poster URL** in `ShikimoriUserRate.toLibraryUiItem()`:
   - Always use `https://smarthard.net/static/animes/$targetId.jpeg` as fallback
