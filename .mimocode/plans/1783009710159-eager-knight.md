# Fix kinobox OOM: streaming JSON parsing

## Problem
`kinobox.tv/api/players` returns **>5MB** JSON for a single movie. Loading it entirely into a String via `response.body?.string()` causes OOM (501MB/512MB heap, fragmentation, crash).

The `readBodyLimited(256KB)` fix we added earlier **breaks kinobox** — it truncates the response before valid JSON is returned.

The kinobox.tv website is down (404), so embedding a player page directly is not an option.

## Solution: Stream-parse the kinobox JSON response

Instead of reading the entire response into a String, use **Okio's BufferedSource** to parse the JSON array incrementally. Extract only `source` + `iframeUrl` from the first few player objects, then close the connection.

This keeps memory usage near-zero regardless of response size.

**Actually, simpler approach:** Use `kotlinx.serialization.json.JsonReader` which is already in the project dependencies. It provides a streaming JSON reader:

```kotlin
private fun parseKinoboxStream(response: okhttp3.Response, maxPlayers: Int = 5): List<DdbbPlayer> {
    val source = response.body?.source() ?: return emptyList()
    val players = mutableListOf<DdbbPlayer>()
    try {
        val reader = kotlinx.serialization.json.JsonReader(source.bufferedReader())
        reader.beginArray()
        while (reader.hasNext() && players.size < maxPlayers) {
            var sourceName = ""
            var iframeUrl = ""
            reader.beginObject()
            while (reader.hasNext()) {
                when (reader.nextName()) {
                    "source" -> sourceName = reader.nextString()
                    "iframeUrl" -> iframeUrl = reader.nextString()
                    else -> reader.skipValue()
                }
            }
            reader.endObject()
            if (iframeUrl.isNotBlank()) {
                players.add(DdbbPlayer(
                    id = "kinobox_${sourceName.lowercase()}",
                    name = "Kinobox: $sourceName",
                    iframeUrl = iframeUrl
                ))
            }
        }
        reader.endArray()
    } catch (_: Exception) {}
    finally { response.close() }
    return players
}
```

This reads only the first 5 player objects and ignores the rest of the 5MB+ response. Memory usage stays near zero.
