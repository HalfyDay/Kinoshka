# JS-плагины источников (вариант C)

Пользовательский источник одним `.js`-файлом по URL — без обновления
приложения. Работает рядом с Embed-ссылками (вариант A) и Stremio-аддонами
(вариант B): общий реестр, разделы Фильмы/Аниме/18+, выключатели, пикер,
плеер, скачивание, шаринг, прокси-флаг, кнопка «Обновить».

Живой шаблон: [`example.js`](example.js) — фильм (`voices`) + сериал/аниме
(`tracks` с лестницей качества) — он же гоняется в юнитах
(`JsPluginDocTest`), так что дока не врёт: если пример сломается,
упадут тесты.

## Установка

1. Источники → вкладка «Свои» → Добавить → вид **«JS-плагин»**.
2. Вставить URL `.js`-файла (http(s), прямой файл, не страница).
3. **«Проверить»** — приложение скачает код, выполнит `manifest()` и резолв
   «Матрицы» (kp=301 / tt0133093), покажет имя/версию/автора и число потоков.
4. **«Сохранить»** — дважды: первый раз показывает предупреждение песочницы,
   второй сохраняет (смена полей сбрасывает подтверждение).
5. Сохранение требует скачанного кода: без «Проверить» сохранить нельзя.

Обновление: кнопка «Обновить код» в строке источника перекачивает файл
и показывает `было → стало` по `manifest.version`. При шаринге JSON
передаётся только URL — код на новом устройстве докачивается сам.

## Контракт файла

Весь файл — обычный JS. Обязательны две функции:

```js
function manifest() {
    // ВЕРНУТЬ JSON-СТРОКУ (именно строку, не объект):
    return JSON.stringify({
        name: "Мой источник",   // 1–40 символов, показывается в пикере
        version: "1.2.0",       // любая непустая строка; по ней — «Обновить»
        author: "@nick",        // необязательно
        description: "…",       // необязательно
        kinoshkaApi: 1          // обязательно ровно 1
    });
}

// s — JSON-строка: {"kinopoiskId": 301|null, "imdbId": "tt0133093"|null}
// (одно из двух может быть null — ветвите сами; для 18+ моста нет,
//  там обычно только прямой imdbId, которого у хентая почти не бывает).
// ВЕРНУТЬ JSON-СТРОКУ {voices[] и/или tracks[]} (пусто = пропуск тайтла).
//
// Плагин НЕ знает, из какого раздела его вызвали: один resolveMovie
// обслуживает все три. Отдавайте обе формы сразу — пикер каждой секции
// заберёт свою: ФИЛЬМ берёт voices[], СЕРИАЛ и АНИМЕ — tracks[]
// (аниме группирует треки по дабу в строки озвучек; voices без tracks
// дадут строки с одной серией — годится для полнометражек).
function resolveMovie(s) { /* … */ }
```

### `voices[]` — фильм (одна строка пикера на элемент)

```js
{ voices: [
    {
        title: "Дубляж",                          // пусто = имя источника
        url: "https://cdn…/master.m3u8",          // только http(s), битые скипаются
        headers: { Referer: "https://host/" }     // необязательно; дефолтов НЕТ —
    }                                             // Referer чужого CDN угадать нельзя
] }
```

### `tracks[]` — сериал (серия на элемент, дабы группируются в строки)

```js
{ tracks: [
    {
        season: 1, episode: 3,                    // episode обязателен (≥1), season дефолт 1
        url: "https://cdn…/s1e3.m3u8",            // fallback-поток (лестницы нет)
        dub: "dublyazh",                          // слаг даба (латиница; дефолт "plugin")
        dubTitle: "Дубляж",                       // подпись даба (дефолт — имя источника)
        title: "Пилот",                           // подпись серии (необязательно)
        qualities: {                             // необязательно: лестница качества —
            "1080p": "https://cdn…/s1e3_1080.m3u8", // играет лучшее (первое не-Auto),
            "720p": "https://cdn…/s1e3_720.m3u8"    // без неё — одиночный Auto
        },
        headers: { Referer: "https://host/" }     // необязательно, на все URL трека
    }
] }
```

Невалидный возврат (не JSON, нет функции, нет валидных URL) = пропуск
источника на этом тайтле, причина — в лог. Пустые `voices`+`tracks` — тоже
пропуск, это штатный способ сказать «тайтла нет на хосте».

## Host API (всё, что видит скрипт)

```js
log("resolve kp=" + ctx.kinopoiskId)              // в лог приложения с тегом плагина

var page = httpGet("https://host/embed/kp/301",   // блокирующий GET
                   { Referer: "https://host/" }); // заголовки необязательны
// → {status: 200, headers: {...}, body: "…", error: ""}
// статус !== 200 → смотреть page.status / page.error, бросать исключение не надо

var r = httpPost("https://host/api/get_stream",   // блокирующий POST
                 "id=301&type=movie",             // тело строкой
                 { "Content-Type": "application/x-www-form-urlencoded" });
```

Сеть идёт через стек приложения: таймауты 6/10 с, потолок тела 512 КБ,
кулдаун мёртвых хостов, прокси (если у источника включён «Через прокси» —
регистрируется хост `.js`-файла). POST закрывает Rezka-style API
(`get_movie`/`get_stream`).

## Песочница и лимиты

- Движок Rhino (чистая Java, Android + desktop). На Android — interpreted-режим.
- `java.*`, `Packages.*` и весь Java-мир закрыты; файлов, сокетов, аккаунтов нет.
- Лимит инструкций + wall-timeout ~25 с на вызов: вечные циклы умирают.
- Каждый вызов — свежие контекст и scope: состояние между резолвами не течёт,
  границу скрипт/приложение пересекают только JSON-строки.
- Файл кода: до 512 КБ в хранилище (`js_plugins/<ID>.js`, в префсах только
  строка реестра). Кэш резолва — как у остальных своих (10 мин).

## Отладка

- «Проверить» в диалоге = живой прогон на «Матрице», вердикт текстом в диалоге.
- `log()` из скрипта виден в logcat под тегом `JsSandbox`.
- Частые причины красного вердикта: функция вернула объект вместо
  `JSON.stringify`, не-http(s) ссылки, `kinoshkaApi !== 1`, пустые потоки
  для Матрицы (хост её правда не имеет — возьмите для пробы тайтл с хоста,
  но health всегда гоняет Матрицу).

## Заведомые ограничения

- Контракт синхронный: сайты с многошаговым JS-рендером (Cloudflare challenge,
  Anubis PoW) не покрываются — нужен WebView-движок (вариант D, пока нет).
- Сериалам нужен поэпизодный разбор на стороне плагина (сезоны/серии из
  embed-сериала); Stremio-вариант для сериалов проще, если хост — аддон.
- Скорость Rhino ниже V8, но резолв — это 1–3 HTTP + парсинг строк.
